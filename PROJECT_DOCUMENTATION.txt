CRM PROJECT DOCUMENTATION
=========================

Project Name
------------
CRM - Waterproofing / Service Business Management System

Project Purpose
---------------
This project is a web-based CRM system built in Laravel. It is used to manage
customers, quotations, invoices, payments, expenses, users, roles, permissions,
settings, and activity logs in one admin panel.

The main goal of the project is to help the company track the complete business
flow:

1. Add and manage customers.
2. Create quotations / estimations for customers.
3. Convert quotations into invoices.
4. Record customer payments against invoices.
5. Record business or project expenses.
6. Check customer-wise payment and expense balance.
7. Manage users and permissions.
8. Keep activity logs for admin tracking.


Technology Used
---------------
Backend: Laravel / PHP
Frontend: Blade templates, Bootstrap, Bootstrap Icons, jQuery, SweetAlert
Database: MySQL
Server Environment: XAMPP local server

11. Customer Ledger Module - Newly Added
----------------------------------------
This is the new module added for customer-wise combined payment and expense
tracking.

Before this change, payments and expenses were separate modules. The boss/user
asked for a combined transaction module where we can see customer-wise:
- How much payment was received
- How much expense was spent
- Net balance for each customer

The Customer Ledger module solves this requirement.

What the Customer Ledger Shows:
- Total number of customers in the filtered result
- Total payment received
- Total expenses
- Net balance
- Customer-wise payment total
- Customer-wise expense total
- Customer-wise net balance
- Number of payment entries per customer
- Number of expense entries per customer

Net Balance Formula:
Payment Received - Expense Amount = Net Balance

Example:
If customer payment received is 100,000 and expense is 25,000:
Net balance = 75,000

If expense is more than payment, net balance will show as negative.

Customer Ledger Filters:
- Search by customer name, company, email, or mobile
- Select one customer
- Sort by net balance
- Sort by payment amount
- Sort by expense amount
- Filter by date range
- Include all customers option

Customer Ledger Popup:
When clicking the eye/view button in Customer Ledger, the selected customer's
ledger opens in a popup. The popup shows:
- Customer payment total
- Customer expense total
- Customer net balance
- Latest combined payment and expense entries
- Entry date
- Entry type: Payment or Expense
- Receipt/expense number
- Linked invoice
- Payment method
- Amount

The popup makes the page easier to use because the user can see details without
leaving the customer ledger listing page.

New URL:
/admin/transactions/customer-ledger

Permission Required:
transactions.view


12. Asset Management Module - Newly Added
-----------------------------------------
This module is used to manage company/godown assets and check whether stock is
available or not.

This is useful for a construction or waterproofing company where many daily
workers use tools, machines, safety items, materials, and other assets from the
godown.

Main purpose:
- Maintain all godown assets in one place
- Check available stock quickly
- Track issued quantity
- Track returned quantity
- Track damaged quantity
- Track maintenance/repair quantity
- Track lost quantity
- See low stock and not available stock

Asset examples:
- Drill machine
- Grinder
- Safety belt
- Helmet
- Scaffolding material
- Waterproofing machine
- Pipe
- Extension wire
- Measuring tape
- Trolley

What the Assets Page Shows:
- Total asset items
- Total quantity
- Available quantity
- Issued quantity
- Problem quantity
- Asset code
- Asset name
- Category
- Godown/location
- Condition
- Stock status
- Quantity split: available, issued, damaged, maintenance, lost

Stock Formula:
Available Quantity =
Total Quantity - Issued Quantity - Damaged Quantity - Maintenance Quantity - Lost Quantity

Example:
Total drill machines: 10
Issued to workers: 4
Damaged: 1
Maintenance: 1
Lost: 0
Available in godown: 4

Stock Status:
- Available: stock is available in godown
- Low Stock: available quantity is less than or equal to minimum alert quantity
- Not Available: available quantity is zero
- Inactive: asset is not currently used

Asset Actions:
- Add Asset
- Edit Asset
- Delete Asset
- Issue to worker/site
- Return to godown
- Add stock
- Mark damaged
- Send to maintenance
- Back from maintenance
- Mark lost

How to Use Asset Management:

Step 1:
Open Assets from the sidebar.

Step 2:
Add asset details such as name, category, unit, godown location, total quantity,
minimum alert quantity, condition, and notes.

Step 3:
Check the asset list to see available stock.

Step 4:
Click the stock action button to issue, return, add stock, mark damaged, send to
maintenance, or mark lost.

Step 5:
Enter quantity, date, worker name, site/project, reference, and notes if needed.

Step 6:
Save the stock action. The available quantity updates automatically.

Why This Feature Is Useful:
- One person can manage godown stock without confusion.
- It avoids manually checking whether an item is available.
- It keeps record of which stock is issued or unavailable.
- It helps identify missing, damaged, or repair items.
- It makes daily construction asset management faster.

New URL:
/admin/assets

Permission Required:
assets.view, assets.create, assets.edit, assets.delete

Why This Feature Is Useful
--------------------------

1. It gives customer-wise financial clarity.
2. It combines payment and expense information in one place.
3. It helps management understand profit/balance per customer.
4. It avoids checking Payments and Expenses pages separately.
5. It gives accountants a fast customer account summary.
6. It helps in project-wise or customer-wise decision making.


Data Source
-----------

Payments:
Data comes from the transactions table.
Only cleared payments are counted in customer ledger totals.

Expenses:
Data comes from the expenses table.
Only approved and paid expenses are counted in customer ledger totals.

Customers:
Data comes from the customers table.
Each payment and expense is grouped by customer_id.


Important Business Logic
------------------------

Payment counted when:
- transaction type is payment
- transaction direction is income
- transaction status is cleared

Expense counted when:
- expense status is approved or paid

Net balance:
- Positive net means customer payments are higher than expenses.
- Negative net means expenses are higher than customer payments.
